# План: админка статей, выкладка на сервер, заявка Riot

Черновик для обсуждения. Порядок: сначала сайт живёт на своём сервере и домене, потом админка статей, потом прототип с Riot API и заявка на production-ключ.

## 0. Что уже готово

- Сайт на русском и английском: русский — адреса без префикса (`/champions`), английский — `/en/…`, переключатель в шапке.
- Данные Riot скачиваются на обоих языках (`npm run update-data`).
- Сгенерированные статьи убраны в `archive/articles/` — на сайте их нет, раздел «Статьи» скрыт, пока нет ни одной статьи.
- `sitemap.xml` (все страницы на обоих языках со ссылками hreflang) и `robots.txt`.
- В подвале — обязательная оговорка Riot (Legal Jibber Jabber) на английском и её перевод.

## 1. Выкладка на свой сервер

Сайт — **riftden.com**, домен на Cloudflare. Сервер общий с другим проектом: его nginx занимает порты 80/443, поэтому у сайта свой контур, который чужой стек не трогает.

```
браузер ──HTTPS──▶ Cloudflare (SSL strict) ──HTTPS :8443──▶ riftden-nginx (сертификат Cloudflare Origin)
                                                               └──▶ riftden-web (next start, :3000)
```

- **Код** — репозитории [Gildra-Foundation/LoL](https://github.com/Gildra-Foundation/LoL) (сайт) и [Gildra-Foundation/core](https://github.com/Gildra-Foundation/core) (движок, подмодуль `packages/engine`).
- **Сборка и запуск** — `deploy/deploy.sh` на сервере: свежий код из GitHub, образ по `Dockerfile`, перезапуск контейнеров из `deploy/compose.yml`.
- **Cloudflare** — `deploy/cloudflare.py`: сертификат Origin, A-запись и www, SSL strict, «всегда HTTPS» и правило Origin Rules «ходить на сервер по порту 8443». Ключ API хранится только на сервере.
- **Адрес сайта** для канонических ссылок и sitemap задаётся при сборке: `SITE_URL=https://riftden.com`.

### Дальше

- **Обновление данных патча** — таймер на сервере раз в сутки: если вышел новый патч Data Dragon, скачать данные, собрать образ и перезапустить.
- **Резервные копии** базы статей (этап 2) — каждую ночь в отдельное хранилище.
- **Наблюдение** — внешний пинг доступности и логи контейнеров.

## 2. Админка статей (первая версия)

### Что умеет

- вход по логину и паролю (один или несколько редакторов);
- список статей: заголовок, язык, статус (черновик / опубликована), дата;
- редактор: текст в Markdown/MDX и рядом живое превью тем же оформлением, что на сайте;
- кнопки вставки компонентов статьи: чемпион, сетка чемпионов, лидеры по характеристике, формула, врезка;
- поля: заголовок, описание, slug, язык, категория, дата, обложка (выбор чемпиона и образа), упомянутые чемпионы, «главная статья»;
- у статьи может быть версия на втором языке — переключатель «RU / EN» в редакторе;
- черновик → публикация → снятие с публикации; удаление с подтверждением.

### Как устроена

- **Хранение** — SQLite (один файл на сервере, копируется для бэкапа). Таблицы `articles` (общие поля: slug, обложка, чемпионы, featured), `article_translations` (язык, заголовок, описание, категория, текст, статус, даты), `users`, `sessions`.
- **Показ на сайте** — страницы `/articles` и `/articles/[slug]` читают базу и обновляются сразу после публикации (`revalidatePath`). Остальной сайт остаётся статическим.
- **Текст** компилируется на сервере тем же `MdxContent`, что и сейчас. Разрешены только компоненты из списка — проверка, как в `npm run check-articles`, переносится в сохранение статьи.
- **Вход** — пароль хранится хешем (argon2), сессия — подписанная cookie `HttpOnly; Secure; SameSite=Lax`, ограничение числа попыток входа, админка под `/admin`: не переводится, закрыта от поисковиков и от прокси языков.
- **Обложки** — арты чемпионов с CDN Riot, загрузка своих картинок — во второй версии.
- **Архивные статьи** при желании можно импортировать черновиками — решать вам.

### Порядок работ

1. База и вход: схема, миграции, страница входа, защита `/admin`.
2. Список и редактор статьи с превью и сохранением черновика.
3. Публикация и показ на сайте, sitemap с опубликованными статьями.
4. Переводы статьи (вторая языковая версия) и импорт архива (по желанию).

## 3. Riot API и заявка на ключ

1. Вы входите на [developer.riotgames.com](https://developer.riotgames.com) и получаете ключ разработчика (он живёт 24 часа — для прототипа хватит).
2. Прототип: страница игрока по Riot ID (`Имя#TAG`) — ранг, мастерство чемпионов, последние матчи. Запросы — только с сервера (`account-v1` → `summoner-v4` → `league-v4`, `champion-mastery-v4`, `match-v5`), с кешем, чтобы не упираться в лимиты; ключ — в переменной окружения, в браузер не попадает.
3. Сайт с прототипом — на домене, файл `apps/lol/public/riot.txt` с кодом подтверждения от Riot.
4. Заявка на production-ключ: описание продукта, ссылка, скриншоты. Правила, которые у нас уже соблюдены или будут соблюдены: бесплатный доступ, оговорка Riot в подвале, нет калькуляторов скрытого MMR, ставок и раскрытия анонимных игроков, ключ только на сервере.
