# Публичный релиз RiftDen

## Допуск

`npm ci`, `npm run verify`, production-сборка, `npm run smoke` и `npm run test:e2e` должны пройти. Проверки браузера включают desktop/mobile, ошибки JavaScript, переполнение, axe, поиск с сетевой ошибкой, ссылку на билд и переход к содержимому.

Цели реальных Web Vitals: p75 LCP ≤ 2500 мс, INP ≤ 200 мс, CLS ≤ 0,1. Браузерный тест не подтверждает реальные p75; после запуска нужны наблюдения. Бюджеты HTML заданы в scripts/smoke.mjs.

## Выпуск

Из проверенного checkout: `sudo ./deploy/release.sh`. Скрипт сохраняет ID предыдущего образа, выполняет проверки, строит образ с уникальным тегом, запускает кандидата на loopback 3015, проверяет и переключает только web. Код не сбрасывается через git reset. При ошибке публичной проверки предыдущий образ восстанавливается. Для ручного отката: `sudo ./deploy/rollback.sh`.

Старые образы автоматически не удаляются: они нужны для отката. Код движка — отдельный git-подмодуль; перед отправкой в GitHub сначала коммитить и публиковать изменения core, затем обновлять ссылку в родительском репозитории. Иначе CI не получит изменённый движок.

## Staging

`docker compose -f deploy/staging.compose.yml up -d --build`: локальная отдельная версия на 3016. В сборке SITE_PREVIEW=true закрывает индексацию; staging не выставляется наружу. Не использовать этот образ для production.

## Наблюдение

`deploy/check-health.sh` проверяет публичный JSON health. Шаблоны systemd запускают проверку раз в пять минут. Результат: `journalctl -u riftden-monitor.service`. Ошибки сервера: `docker logs riftden-web`. Внешние уведомления требуют отдельно выбранного адресата; скрипт никому не отправляет сообщения.

## Внешние действия владельца

- Подтвердить домен в Google Search Console и Яндекс Вебмастере, отправить https://riftden.com/sitemap.xml.
- Проверить отчёты индексирования и Core Web Vitals после накопления данных.
- Указать канал обратной связи и согласовать тексты анонсов. Анонсы без явного указания адресатов не отправляются.
- Хранить резервные копии контента и данных вне сервера; локальный архив не защищает от потери сервера.

## Контроль дизайна

Система HUD: DESIGN.md, токены apps/lol/src/styles/theme.css и общие packages/engine/styles/base.css; витрина /design. Не дублировать цвета и размеры в компонентах новой игры. Проверять фокус и reduced motion вместе с основными сценариями.

## Метрики без внешнего сервиса

Компонент SiteMetrics отправляет Web Vitals и посещения разделов в /metrics. Не используются cookies, идентификаторы, полный адрес, параметры, user-agent или IP в записи метрики. Учитывается Do Not Track. Записи выводятся в журнал контейнера; входящий payload ограничен 1 КиБ и проверяется.

Отчёт: `docker logs riftden-web 2>&1 | node scripts/metrics-report.mjs`. Это показатели отдельных загрузок/взаимодействий, а не уникальных посетителей. Настроить ротацию Docker-журнала; долгосрочные отчёты требуют отдельного хранения.

## Кеш изображений и место на сервере

Кеш изображений находится в tmpfs с пределом 128 МиБ и очищается при пересоздании контейнера. Это позволяет процессу node писать кеш при отсутствии свободных блоков для обычных пользователей на диске сервера. Необходимо отдельно освободить место или расширить диск; чужие файлы и образы не удалялись.
